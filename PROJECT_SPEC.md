# Conference Atlas — project specification

This document is the **single source of truth** for humans and LLMs. It explains **why** the repo exists, **what** each part does, **how** to run and deploy it, **how** provenance works (so outputs are not mistaken for hallucinations), and **how** to add conferences through UIs.

If you are rebuilding the repository from scratch, implement exactly what is described here.

---

## 1. Purpose (why)

**Goal:** Build a **repeatable research surface** over European **music industry conference programmes**: scrape public programme pages, turn messy text into **structured JSON**, then **synthesize cross-event patterns** (shared themes, emerging threads, gaps). Ship a **calm editorial Next.js site** suitable for strategy reviews, plus optional **HTML brief** for offline sharing.

**Non-goals:** Live calendars, ticketing, organizer affiliation, or “official” schedules — only **public programme pages** as evidence.

**Trust / anti-hallucination posture:** Every insight on the public site must be **traceable** to:
1. A **real URL** configured per conference (`web/conferences.json`).
2. **Scraped markdown** stored locally at `data/raw/{id}.json` (optional to commit; default gitignore).
3. **Per-event extraction JSON** at `data/extracted/{id}.json` (LLM structured output from that scrape).
4. **Exported bundles** under `web/public/data/` for Vercel: `synthesis.json`, `meta.json`, **`provenance.json`** (human-readable excerpts + hashes + counts so readers see **what text entered the model**).

The site must include a **Sources / evidence** page reading `provenance.json` so users can verify inputs without opening Python data folders.

## 3. Data flow (how)

1. **Configure events** — Edit `web/conferences.json` (array of objects with required `name`, `year`, `url`; optional `id`, `city`, `country`). `id` defaults to slugified `name`.

2. **Scrape** (`python run.py --scrape`) — Firecrawl fetches each `url`, stores markdown in `data/raw/{id}.json` with `scraped_at`, `error`, `raw_content`.

3. **Extract** (`python run.py --extract`) — Claude turns markdown into structured sessions/themes in `data/extracted/{id}.json`. Each file includes `_meta.source_url`, `_meta.scraped_at` pointing back to the scrape.

4. **Synthesize** (`python run.py --synthesize`) — Single Claude call over all extractions → `data/synthesis.json`.

5. **Report** (`python run.py --report`) — Jinja2 → `report.html`; calls **`export_for_next()`** which copies synthesis + writes `meta.json` + **`provenance.json`** into `web/public/data/`.

**CLI shorthand:** `python run.py --all` runs scrape → extract → synthesize → report (no mock unless `--mock` on scrape/all).

**Model id:** `claude-sonnet-4-5-20250929` (config constant in `config.py`). If your Anthropic account returns 404 for this id, run a models list with your API key and set `CLAUDE_MODEL` to an available Sonnet family id.

## 4. Vercel deployment

Pick **one** layout in the Vercel project (**Settings → Build & Deployment → Root Directory**):

### A) Root Directory = `web` (recommended)

- Leave **Install** / **Build** as defaults (or rely on `web/vercel.json`, which only sets `"framework": "nextjs"`).
- Vercel reads `web/package.json`, which lists `next` in `dependencies` — this fixes **“No Next.js version detected”**.
- Do **not** use a root `vercel.json` that runs `cd web && …` here: from `web/` that path is wrong.

### B) Root Directory = repo root (Git checkout root)

- Root `package.json` and `package-lock.json` also declare `next` so version detection succeeds.
- Root `vercel.json` is required with:
  - `"framework": "nextjs"`
  - `"installCommand": "npm install --prefix web"`
  - `"buildCommand": "npm run build --prefix web"`
- Uses `npm --prefix web` instead of `cd web` for consistent paths.

### General

- **Never** ship Flask as the Vercel entrypoint; Python stays local.
- **Secrets:** only for the local pipeline (`.env`). The static site does not need API keys on Vercel.
- **Static data:** Commit `web/public/data/synthesis.json` (+ `provenance.json` after a run) so production shows real output; `meta.json` timestamps the export.

## 5. Adding conferences (UI requirements)

Two supported UIs (both must exist):

### A) Local Flask dashboard

- **Run:** `pip install -r requirements-dashboard.txt && python dashboard.py` → `http://127.0.0.1:5050`
- **Features:** Add conference form (`POST /api/conferences`) appends to `web/conferences.json`; run pipeline steps via `POST /api/run`; status table shows raw/extract presence per event.

### B) Next.js UI

- **Conferences** page lists cards + **source links**.
- Include an **“Add conference”** form served by the Next app:
  - **Local dev (`next dev`):** Server Action may **write** `web/conferences.json` on disk.
  - **Vercel production:** By default the Server Action **refuses** to write (read-only filesystem) and returns an explanatory error. Optional escape hatch: set env `**ALLOW_VERCEL_CONF_WRITE=1**` only if you add a real writable backend later — do **not** rely on this alone without implementation.
  - **Never** silently pretend a save succeeded on production.

This satisfies “add via UI” for developers while staying honest about hosting limits.

## 6. Provenance on the public site (`provenance.json`)

`export_web.build_provenances()` produces `web/public/data/provenance.json`, an array of objects shaped like:

- `id`, `name`, `year`, `source_url`
- `scraped_at`, `scrape_error` (if any), `raw_chars`
- **`raw_excerpt`** — first ~1 200 characters of scraped markdown (proof of input)
- **`raw_sha256_prefix`** — short hash fingerprint of full raw text (optional; helps detect edits)
- `extracted_session_count`, `extraction_note`, `extraction_meta` (from `_meta` in extraction)

Next.js route **`/sources`** reads this JSON and renders accordions/cards so **stakeholders see what was fed into the LLM** before trusting synthesis bullet points.

## 8. Node version (local Next)

- **Use Node 20 or 22 LTS.** Node 23+ often breaks Next dev chunks.
- `web/.nvmrc` = `22`
- `web/scripts/check-node.mjs` exits non‑zero on Node ≥ 23
- `npm run dev` should run `rm -rf .next && next dev` to avoid stale webpack chunks (optional `dev:incremental` without delete)

## 10. Design language (Next site)

- **Dark editorial UI:** ink / parchment / gold palette (Tailwind theme).
- **Fonts:** Cormorant Garamond + DM Sans (next/font/google).
- **Pages:** Home (`/`), Insights (`/insights`), Conferences (`/conferences` + add form), Methodology (`/methodology`), **Sources** (`/sources`).
- **Insights** normalizes synthesis JSON with `lib/normalize.ts` (topic shape flexibility).

## 11. LLM maintenance notes

- When **adding a conference**, always use a **programme URL** that returns substantive text; validate in `dashboard` status table.
- When **upgrading Next**, keep `engines` to `<23` until Next officially supports newer Node for this stack.
- If synthesis looks “wrong,” inspect **`provenance.json` excerpts** and `data/raw/` locally — the bug is usually scrape quality or truncation (`EXTRACT_MAX_INPUT_CHARS`), not random hallucination.
- **Absent topics** in synthesis are **model-inferred gaps** — label them as hypotheses in copy (already in Insights absent section).
